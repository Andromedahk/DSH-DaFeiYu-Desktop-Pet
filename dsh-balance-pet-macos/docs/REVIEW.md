## 1.1.1 账号验证登录修复

问题：1.1.0 收紧 YAML 解析后，仅接受账号记录内的直接 `token` / `issuer` 字段，遗漏了 DSH 实际保存的 `deepseek-account-platform/default.payload` 包装结构，导致账号已登录仍显示“找不到凭证”。

修复：明确支持 `payload` 内同级的 token 与 issuer，同时兼容旧版直接结构；忽略无关 metadata，拒绝跨节点混配、重复字段和异常 payload。保持 HTTPS 校验及禁止认证重定向的规则。无需改用 API Key，也不修改用户的 DSH 凭证。

验证：新增 16 项针对性回归，全部 122 项离线断言及完整 `verify.sh` 通过；universal 编译通过。使用本机现有账号登录凭证运行新版应用，状态确认为“已连接”，来源为 DSH 账号，余额可显示。实际 token、账号信息与余额数值均未写入仓库或测试夹具。1.1.0 中关于未验证真实账号接口的说明是当时的验证边界，本次已补上本机账号模式的实测。

## 1.1.2 菜单布局修复

问题：右键菜单的二级菜单能够展开，但显示区域被压缩为窄条；部分情况下主菜单文字也被截断。辅助功能条目存在且动作可执行，不能据此判断菜单视觉显示正常。

调整：使用原始鼠标事件的屏幕坐标，在不绑定桌宠视图的情况下弹出菜单；主菜单和所有子菜单通过 `confinementRect` 使用所在屏幕的可见区域。菜单跟踪期间停止修改窗口的鼠标穿透属性，并且只在根菜单关闭后恢复。菜单栏的结构刷新移至 `menuNeedsUpdate`，避免在 `menuWillOpen` 中修改正在显示的菜单。

验证：universal 编译、严格签名校验、122 项离线断言和完整 `verify.sh` 通过。临时几何诊断确认演示子菜单实际为 118×130 pt、刷新间隔子菜单实际为 78×106 pt，与各自常规尺寸一致，父子菜单均在正常菜单层级；用户确认新版菜单正常。临时诊断代码不包含在交付应用或源码中。

测试期间的独立离线实例已关闭；最终保留的正式版使用原有配置目录，重启后凭证来源确认为 DSH 账号、状态为“已连接”。用户账号凭证和实际余额均未写入仓库。离线测试结果与正式账号连接结果分别验证，避免把离线实例的“无凭证”当作正式版状态。
